# 安裝與使用說明

Leaf 是一款可即時預覽的 Markdown 編輯器，兼顧專注寫作與文稿審閱。這份說明幫助你從安裝開始，逐步熟悉日常寫作、排版與審閱操作。

## 安裝與首次開啟

前往 [Leaf 下載頁面](https://github.com/CoozeeWang/leaf-markdown/releases)，選擇適合你電腦的安裝檔。下載前請閱讀對應版本的發布說明，確認系統要求與已知問題。

| 電腦 | 安裝檔 | 安裝方式 |
| --- | --- | --- |
| Windows x64 | [Leaf-1.0.3-windows-x64-setup.exe](https://github.com/CoozeeWang/leaf-markdown/releases/download/v1.0.3/Leaf-1.0.3-windows-x64-setup.exe) | 按兩下安裝檔，依提示安裝。 |
| Mac（M 系列晶片） | [Leaf-1.0.3-macOS-arm64.dmg](https://github.com/CoozeeWang/leaf-markdown/releases/download/v1.0.3/Leaf-1.0.3-macOS-arm64.dmg) | 開啟 DMG，將 Leaf 拖入「應用程式」資料夾，再從該資料夾開啟。 |

以上 Mac 安裝檔適用於 Apple Silicon，不適用於 Intel Mac。Windows 首次安裝時，如果電腦缺少 WebView2 執行環境，安裝器可能需要連網準備。

安裝新版前，請先儲存文稿並結束舊版 Leaf。正常覆蓋更新無需先解除安裝，也無需清空設定。

**Windows 更新提醒：** 如果安裝過程出現解除安裝步驟，請勿勾選「刪除應用程式數據」。在一般解除安裝流程中勾選此項，會清除 Leaf 設定與 MCP 連線設定。正常取代舊程式檔案是另一回事，可依提示繼續。

### 系統與執行環境

- **Mac**：僅提供 Apple Silicon（M 系列）安裝檔。編譯最低目標為 macOS 11.0；這不代表已在所有 macOS 11 及以上版本完成相容性驗證。介面使用系統內建的 WebKit，舊系統的呈現效果可能不同。
- **Windows**：提供 x64 安裝檔，適用目標為 Windows 10 / 11，需要 Microsoft Edge WebView2 Runtime；缺少時安裝程式可能需要連網安裝。執行環境的官方支援範圍不等同於 Leaf 在每個系統版本上的實測結果。

本版尚無涵蓋上述全部系統版本的實機驗收紀錄。

### 首次開啟安全提示

本版 Mac 僅有臨時簽章（ad-hoc），沒有 Developer ID 發行簽章或 Apple 公證；Windows 沒有 Authenticode 數位簽章。請先確認安裝檔來自 [Leaf 官方發布頁](https://github.com/CoozeeWang/leaf-markdown/releases/tag/v1.0.3)，並核對檔案。

- **Mac**：先嘗試開啟 Leaf。如果提示 Apple 無法驗證或無法驗證開發者，前往「系統設定」→「隱私權與安全性」，點選「強制打開」（如有），依提示確認。請參閱 [Apple 說明](https://support.apple.com/zh-tw/102445)。
- **Windows**：如果 SmartScreen 提示「Windows 已保護您的電腦」，點選「其他資訊」→「仍要執行」（如有）。按鈕文字可能因系統版本而異。請參閱 [Microsoft 說明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。

以上步驟僅適用於已確認來源的未識別開發者或未知信譽提示。如果提示惡意軟體、檔案損毀、驗證失敗，或受到組織原則限制，請停止安裝並透過 [Issues](https://github.com/CoozeeWang/leaf-markdown/issues) 聯絡我們；請勿關閉系統防護。瀏覽器下載警告、使用者帳戶控制與 Smart App Control 並非同一種提示。

發布頁中的 SHA256 與 Minisign 分離簽章用於核對檔案完整性與來源，不等同於系統認可的發行簽章，也不保證安裝時沒有警告。

## 開啟與儲存文稿

開啟 Leaf 後，可以新增文件，也可以開啟或拖入已有的 Markdown 檔案。

- **儲存**：將目前修改寫入檔案。新文件首次儲存時，需要選擇檔名和儲存位置。
- **另存新檔**：將目前內容儲存到另一個檔案，適合製作副本或保留不同稿件。
- **自動儲存**：文件已有儲存位置時，修改會自動寫入檔案。請留意介面上的儲存狀態；「等待自動儲存」不等於已經儲存完成。

如果 Leaf 提示原檔案找不到，或檔案已被其他程式修改，請先保留目前編輯內容，按照提示重新定位檔案或另存新檔。

**自動儲存與草稿復原是兩件事。** 前者更新文件檔案，後者保留可供意外中斷後找回的編輯內容。重要文稿仍建議定期備份。

## 文件屬性

文件屬性用於記錄內文之外的資訊，例如作者、日期和標籤。你可以在文稿頂端集中檢視和編輯這些資料，無需把它們寫進內文。

### 新增與編輯

在編輯檢視中，將游標放在文件最開頭的空白第一行，連續輸入三個半形短橫線 `---`，Leaf 會自動建立文件屬性區域。你也可以在命令面板中搜尋「文件屬性」來新增。

點選「新增屬性」，填寫屬性名和初始值，並選擇適合的類型，例如文字、日期、數字或核取方塊。

已有屬性可以直接修改名稱和內容；點選屬性類型圖示，可以更改類型。需要刪除某項屬性時，將它的屬性名和屬性值都清空。

在編輯檢視中，可以透過「顯示 → 文件屬性」展開或收起屬性區域。收起只改變顯示，不會刪除屬性。

### 儲存與閱讀

屬性儲存在 Markdown 檔案開頭的 YAML 區域，隨文稿一起儲存和移動，通常無需手寫這些標記。原始碼檢視會顯示原始 YAML；結構較複雜、無法直接編輯的屬性，請在原始碼檢視中修改。

如果習慣直接輸入，也可以切換到原始碼檢視，在文件最開頭用兩行 `---` 包住屬性，例如：

```yaml
---
日期: 2026-10-24
標籤: [寫作, 草稿]
---
```

**編輯檢視中的內文全選不會選取文件屬性。** 在內文中按 `⌘A`（Mac）或 `Ctrl+A`（Windows），只會選取內文，便於複製或替換文章內容時保留屬性。如果需要連同屬性一起複製或刪除，請切換到原始碼檢視，再全選。

屬性不作為內文標題列入大綱。閱讀檢視會在文稿頂端呈現屬性；匯出 PDF 時，可以透過「文件屬性」選項決定是否包含它們，預設不勾選。

## 編輯與閱讀

### 選擇適合目前工作的檢視

| 檢視 | 適合做什麼 |
| --- | --- |
| 編輯 | 一邊寫作，一邊看到標題、粗體、清單等格式的呈現效果。 |
| 原始碼 | 檢視和修改原始 Markdown 標記，檢查連結、空白行或複雜格式。 |
| 閱讀 | 通讀排版後的文稿，減少編輯控制項的干擾。 |

三種檢視使用同一份文稿，無需在它們之間複製內容。需要修改內文、註腳或批註時，請切換到編輯或原始碼檢視。

### 常用格式

可以直接輸入 Markdown，也可以使用格式工具列或快捷鍵，為文字套用粗體、斜體、醒目標示、刪除線、連結，或插入標題、清單、引用、表格、程式碼區塊和提示區塊。

編輯表格時，可以直接修改儲存格內容，並透過表格控制項新增或刪除列、欄。需要檢查原始寫法時，切換到原始碼檢視即可。

### 快捷鍵，隨用隨看

將滑鼠懸停在相應控制項上，即可檢視快捷鍵提示。不必記住上百個快捷鍵，也能逐漸熟悉鍵盤操作，把注意力留給寫作。

### 專注模式

需要更安靜的寫作介面時，可以開啟「專注模式」。按 `Esc` 離開。

### 富文字複製、貼上與拖放（1.0.4）

以下說明適用於準備中的 1.0.4；本頁上方下載連結仍指向已發布的 1.0.3，待新版正式發布後更新。

使用「複製為富文字」（Mac `⌘⇧C`，Windows `Ctrl+Shift+C`）可複製帶格式的內容，同時提供可讀純文字；接收軟體決定採用哪一種。一般複製與此功能是不同入口。貼上時，Leaf 將來源提供的 HTML 轉換為 Markdown，而非保留原始網頁版面；編輯和原始碼檢視使用相同轉換。若來源只提供標題純文字，Leaf 無法還原其中未包含的連結目標。

新增提示區塊的內文為空，標題和內文提示僅為預留文字；既有「內容」等真實文字不會被刪除。在標題按 Enter 進入內文，在最後的空白一般段落再按 Enter 離開區塊。提示區塊內文同樣支援富文字貼上，保留已驗證的命名連結，包括「檔案名稱, 00:00, (5)」這樣的完整標籤，並可一次復原。

外部富文字可拖至內文落點，整次插入可一次復原；內部文字移動、圖片匯入和拖入 Markdown 檔案開啟文件維持原有行為。一般編輯預覽會隱藏有效的逸出標記，游標進入對應字元時可編輯原始碼；原始碼檢視中的 `\[` 用於保留字面方括號，不會從檔案刪除。

Ripple 有效的 v2 來源連結會保留命名標籤，包括正式版 `ripple-transcript` 和開發版 `ripple-segment-dev`。編輯檢視以 Mac `⌘`／Windows `Ctrl` 加點擊開啟連結，閱讀檢視可直接點擊。儲存、貼上與拖放本身不會啟動應用程式。需要安裝並註冊對應版本的 Ripple；其他軟體是否保留或開啟連結取決於該軟體。一般網頁、郵件、文件錨點與相對檔案連結維持既有處理；不支援任意應用程式協定。

Mac 日用修復版已由使用者驗收；Windows 建置、自動測試及使用者安裝驗收分別記錄，Windows 真實跨應用程式拖放與返回來源仍待驗收。

## 檢視與審閱

### 大綱導航

大綱按照標題層級呈現文章結構。點選其中的標題，即可跳至對應章節。如果某一節沒有出現在大綱裡，請確認它使用了標題格式。

### 註腳側邊欄

將游標放在需要插入註釋的位置，使用「插入註腳」控制項或快捷鍵，再填寫註腳內容。內文以註腳標記指向註腳內容，側邊欄便於對照內文，總覽註釋並進行編輯。所有註腳亦可在文末看到。

在註腳側邊欄中，按兩下註腳內容或按 Enter 可以進入編輯；透過返回內文的控制項，可以定位對應的引用標記。刪除註腳時，會一併刪除它在內文中的全部引用，操作可以還原。

註腳採用 Markdown 註腳格式儲存。若提示「缺少註腳定義」，可以切換到原始碼檢視，檢查引用標記是否有對應的定義。

### 文稿批註

在同一段落內選取文字，使用「新增批註」，即可記錄修改意見；也可以把游標放在內文文字之間，為目前位置新增批註。

開啟批註側邊欄，可以集中檢視意見並定位內文。按兩下批註內容或按 Enter 可以編輯；刪除批註會保留對應的內文文字。

Leaf 也支援 Obsidian 的隱藏式批註 `%%批註內容%%`：在編輯檢視中保留原文，在閱讀內文中隱藏，並在批註側邊欄列出。

註腳和批註共用右側欄，透過對應標籤切換檢視。

## 顯示與排版

### 主題、字型與閱讀寬度

在「設定 → 外觀與排版」中，可以選擇淺色、深色或跟隨系統主題，並調整內文字型、內文字級與內文最大寬度。

這些設定幫助你找到舒適的閱讀與寫作佈局，不會將字型、字級或寬度寫成 Markdown 內文。

### 顯示行號

在格式工具列的「顯示」中開啟「原始碼行號」，內文左側會顯示 Markdown 原始檔的行號，方便定位和描述問題。

請注意，行號不是段落編號。一行文字因視窗變窄而自動折成多行時，仍屬於同一行原始碼；編輯檢視中的空白行可能不顯示號碼，因此號碼不一定連續。

行號只是介面提示，不會加入或儲存到文稿文字中。

### 標題分級序號

在「顯示」中開啟「標題多層次編號」，Leaf 會按標題層級顯示類似「1」「1.1」「1.2」的序號，幫助辨認文章結構。

**這些序號是虛擬的顯示效果，不會新增到標題文字中，也不會寫入 Markdown 檔案。** 關閉後，標題恢復為不帶這些序號的顯示方式。

如果希望標題文字本身包含編號，請手動輸入。這個功能也不同於內文中的有序清單。

### 段落空白行整理

Markdown 中的空白行用於分隔段落和不同內容區塊。「整理段落空白行」可以補齊缺少的分隔、刪除多餘空白行，並清理文件首尾空白行。

在編輯或原始碼檢視中，點選工具列的「整理段落空白行」；也可以在命令面板搜尋這個名稱。

**這項操作會修改整篇文稿的 Markdown 內容。** 需要還原時，使用一次「還原」即可撤回整次整理。它與「顯示」中的格式標記不同：格式標記只控制換行等標記是否可見，不會修改內文。

| 位置 | 整理結果 |
| --- | --- |
| 普通段落之間 | 保留一個空白行；缺少時補充，多餘時刪除。 |
| 段落與標題、清單、表格等獨立內容區塊之間 | 保留一個空白行。 |
| 同一清單的相鄰項目、上層項目與子清單之間 | 去除多餘空白行，保留層級和縮排。 |
| 清單項內部的多個段落 | 保留必要空白行，避免結構改變。 |
| 文件開頭和末尾 | 清理多餘空白行。 |

例如，整理前：

```markdown
第一段
第二段


- 第一項

- 第二項
```

整理後：

```markdown
第一段

第二段

- 第一項
- 第二項
```

普通內文中，直接相接的兩行文字會按兩個段落整理，在中間補一個空白行；清單項的續行不會這樣拆開。如果你有意在同一段落內手動折行，請先確認是否需要整理。

文件屬性、程式碼區塊、HTML 區塊、引用、提示區塊和註腳定義內部的空白行會保留；跨行的行內格式也會受到保護。整理不會更改清單文字或縮排，但觸及的有序清單會沿用自動編號規則，保持編號連續。

需要仔細核對整理結果時，可以切換到原始碼檢視查看，再儲存文稿。

## 圖片與 PDF

### 圖片管理

插入文件的圖片會儲存到文件旁的對應資料夾。例如：

```text
旅行筆記.md
旅行筆記.assets/
```

**移動、備份或傳送文件時，請把 `.md` 檔案和對應的 `.assets` 資料夾一起帶上，保持相對位置不變。** 只傳送 Markdown 檔案，接收者可能無法看到其中的本機圖片。

對於文稿中原本引用的其他本機圖片，也需要保留它們對應的檔案及相對路徑。

### 匯出 PDF

使用「匯出 PDF」，先檢視匯出預覽，再按介面提示儲存。如果開啟了系統列印視窗，請選擇儲存為 PDF。

預覽用於檢視文稿樣式，不顯示實際分頁。匯出後建議開啟 PDF，檢查標題、圖片、表格和跨頁位置。

註腳會作為文末註釋呈現。**PDF 不包含文稿批註、隱藏式批註及批註標記。** 需要保留審閱意見時，請保留 Markdown 原稿。

## 草稿復原與應用程式更新

### 找回未儲存的修改

如果出現「有可復原的內容」提示，可以點選檢視；也可以進入「設定 → 儲存與復原」，選擇「檢視可復原草稿」。

復原內容會替換目前編輯內容，操作可以還原。復原後，請先檢查文稿，再手動儲存；復原後自動儲存會暫停，避免未經確認就覆蓋檔案。

「儲存與復原」中還可以設定復原紀錄的保留時間，以及復原最近一次儲存前的版本。這些紀錄有保留期限，不替代長期備份。

### 檢查更新

Leaf 1.0.3 可在應用程式內檢查更新並查看發布說明，再透過瀏覽器前往官方下載頁面。請先儲存文稿並正常結束 Leaf，再手動安裝新版：Mac 在「應用程式」原位置取代 Leaf，Windows 依安裝程式提示覆蓋原安裝。本版不會在應用程式內下載安裝或自動結束並重新啟動。

在同一系統使用者下，保留原安裝位置、不解除安裝也不清空資料夾，正常覆蓋安裝會保留持久設定與應用程式資料。此說明不包含更換使用者、遷移資料或移動隧道程式資料夾的情況。暫時連線需要重新建立；外部 AI 軟體（包括 ChatGPT）的 MCP 授權可能需要重新確認。

**Windows 更新提醒：** 如果安裝過程出現解除安裝步驟，請勿勾選「刪除應用程式數據」。在一般解除安裝流程中勾選此項，會清除 Leaf 設定與 MCP 連線設定。正常取代舊程式檔案是另一回事，可依提示繼續。

使用 1.0.1 或 1.0.2 時，請先從發布頁手動安裝一次 1.0.3。

## AI 輔助編輯

Leaf 目前支援透過 MCP 連接 **ChatGPT、Claude（桌面版）和 WorkBuddy**，協助編輯與審閱文稿。使用前須完成對應軟體的 MCP 連線設定。

如需讓 AI 讀取和修改文稿，可在「設定 → AI 輔助編輯」中啟用 MCP 連線。具體設定步驟見 [AI 輔助編輯與 MCP 連線](AI_CONNECTIONS.zh-TW.md)。

開啟並連線後，AI 可以存取已開啟的文稿，包括未儲存的內容；相關文字會傳送到你使用的 AI 服務。請按文稿內容與自己的需要決定是否啟用。
