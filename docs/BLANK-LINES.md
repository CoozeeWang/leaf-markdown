# 整理段落空行

“整理段落空行”会补齐缺少的分隔，删除多余的分隔，并清理文档首尾空行。整理会修改 Markdown 正文，修改后的内容按当前文档的保存方式保存。

## 如何使用

在编辑或源码视图中，点击工具栏的“整理段落空行”，或在命令面板搜索这个名称。也可以使用快捷键：macOS 为 `⌥⌘\`，Windows 为 `Ctrl+Alt+\`。

整理作用于整个文档。需要还原时，一次撤销即可恢复整次整理；再次整理已经符合规则的文档，不会继续改变内容。

鼠标悬浮提示保持“整理段落空行”和现有快捷键。“显示”中的“编辑标记”仅控制标记是否可见，开关它不会整理或修改正文。

## 空行规则

只有空格或制表符的行也算空行。

| 位置 | 整理结果 |
| --- | --- |
| 文档开头 | 正文前没有空行 |
| 文档末尾 | 最后一行内容后没有空白行 |
| 普通段落之间 | 有且只有一个空行；缺少时补充，多余时删除 |
| 段落与标题、列表、表格、引用、代码块等独立块之间 | 有且只有一个空行 |
| 同一列表的相邻列表项之间 | 没有空行；适用于无序、有序和任务列表 |
| 列表项文字与其子列表之间 | 没有空行；原有层级和缩进保持不变 |
| 列表项内的多个独立段落或其他独立块之间 | 保留一个必要空行，避免段落合并或结构改变 |
| 两个不同的列表之间 | 保留一个空行，保持它们各自的归属 |

文档首尾规则优先：第一段前和最后一段后不需要额外空行。最后一行原有的结尾换行可以保留；它用于结束这一行，不算额外空白行。整理不会给没有结尾换行的文档另加一个。

普通正文中，每个未被特殊结构包裹的源码文本行按独立段落整理。因此，两行普通文字直接相接时，会在它们之间补一个空行。列表项的续行保持原有换行，不会被拆成多个段落。

## 需要保护的内容

有些空行属于内容，或决定 Markdown 的结构，不能一律删除：

- 文档属性、代码块、HTML 块、引用和提示块内部的空行保留原样；这些块中包含的列表也随所在块保留。
- 脚注定义内部的空行保留原样。
- 跨行的行内代码、链接、加粗等内容保留原样。
- 列表项里有多个段落时，段落之间仍需一个空行；列表项中的代码块保留代码内部的空行。
- 尚未闭合的代码块或 HTML 块可能把文档末尾空行视为自身内容，这些空行也受保护。

整理不改列表文字、项目符号或缩进。有序列表沿用 Leaf 的自动编号规则：整理触及的列表会保持编号连续，起始编号不变。例如，原有 `1、3` 的列表在整理项间空行时会变成 `1、2`，这一变化与空行整理一起撤销。

## 整理前后示例

下面的普通段落缺少分隔，列表项之间又有多余分隔：

```markdown
第一段
第二段


- 第一项


- 第二项

```

整理后：

```markdown
第一段

第二段

- 第一项
- 第二项
```

嵌套列表会去掉项间空行，并保留层级：

```markdown
- 父项

  - 子项一

  - 子项二

- 下一项
```

整理后：

```markdown
- 父项
  - 子项一
  - 子项二
- 下一项
```

一个列表项有两个段落时，段落间保留必要分隔，下一项前没有空行：

```markdown
- 第一项的第一段

  第一项的第二段
- 第二项
```

编辑预览、源码和保存后的文档使用同一份整理结果。若要确认具体空行，可切到源码视图；保存后重新打开，内容应与保存前一致。
