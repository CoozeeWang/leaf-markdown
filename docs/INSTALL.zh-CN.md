# 安装与使用说明

Leaf 是一款可实时预览的 Markdown 编辑器，兼顾专注写作与文稿审阅。这份说明帮助你从安装开始，逐步熟悉日常写作、排版与审阅操作。

## 安装与首次打开

前往 [Leaf 下载页面](https://github.com/CoozeeWang/leaf-markdown/releases)，选择适合你电脑的安装包。下载前请阅读对应版本的发布说明，确认系统要求与已知问题。

| 电脑 | 安装包 | 安装方式 |
| --- | --- | --- |
| Windows x64 | [Leaf-1.0.3-windows-x64-setup.exe](https://github.com/CoozeeWang/leaf-markdown/releases/download/v1.0.3/Leaf-1.0.3-windows-x64-setup.exe) | 双击安装包，按提示安装。 |
| Mac（M 系列芯片） | [Leaf-1.0.3-macOS-arm64.dmg](https://github.com/CoozeeWang/leaf-markdown/releases/download/v1.0.3/Leaf-1.0.3-macOS-arm64.dmg) | 打开 DMG，将 Leaf 拖入“应用程序”文件夹，再从该文件夹打开。 |

以上 Mac 安装包适用于 Apple Silicon，不适用于 Intel Mac。Windows 首次安装时，如果电脑缺少 WebView2 运行环境，安装器可能需要联网准备。

安装新版前，请先保存文稿并退出旧版 Leaf。正常覆盖更新无需先卸载，也无需清空设置。

**Windows 更新提醒：** 如果安装过程中出现卸载步骤，请保持“删除应用程序数据”未勾选。在普通卸载中勾选此项会清除 Leaf 设置和 MCP 连接配置。正常替换旧程序文件是另一回事，可按提示继续。

### 系统与运行环境

- **Mac**：仅提供 Apple Silicon（M 系列）安装包。编译最低目标为 macOS 11.0；这不代表已在所有 macOS 11 及以上版本完成兼容性验证。界面使用系统自带的 WebKit，旧系统的渲染表现可能不同。
- **Windows**：提供 x64 安装包，面向 Windows 10 / 11，需要 Microsoft Edge WebView2 Runtime；缺少时安装器可能需要联网安装。运行环境的官方支持范围不等同于 Leaf 在每个系统版本上的实测结果。

本版尚无覆盖上述全部系统版本的实机验收记录。

### 首次打开安全提示

本版 Mac 仅有临时签名（ad-hoc），没有 Developer ID 发行签名或 Apple 公证；Windows 没有 Authenticode 数字签名。请先确认安装包来自 [Leaf 官方发布页](https://github.com/CoozeeWang/leaf-markdown/releases/tag/v1.0.3)，并核对文件。

- **Mac**：先尝试打开 Leaf。如果提示 Apple 无法验证或无法验证开发者，前往“系统设置” → “隐私与安全性”，点击“仍要打开”（如有），按提示确认。参阅 [Apple 说明](https://support.apple.com/zh-cn/102445)。
- **Windows**：如果 SmartScreen 提示“Windows 已保护你的电脑”，点击“更多信息” → “仍要运行”（如有）。按钮文字可能因系统版本而不同。参阅 [Microsoft 说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。

以上步骤仅适用于来源已确认的未识别开发者或未知信誉提示。如果提示恶意软件、文件损坏、核验失败，或受到组织策略限制，请停止安装并通过 [Issues](https://github.com/CoozeeWang/leaf-markdown/issues) 联系我们；不要关闭系统防护。浏览器下载警告、用户账户控制和 Smart App Control 并非同一种提示。

发布页中的 SHA256 与 Minisign 分离签名用于核对文件完整性与来源，不等同于系统认可的发行签名，也不保证安装时没有警告。

## 打开与保存文稿

打开 Leaf 后，可以新建文档，也可以打开或拖入已有的 Markdown 文件。

- **保存**：将当前修改写入文件。新文档首次保存时，需要选择文件名和保存位置。
- **另存为**：将当前内容保存到另一个文件，适合制作副本或保留不同稿件。
- **自动保存**：文档已有保存位置时，修改会自动写入文件。请留意界面上的保存状态；“等待自动保存”不等于已经保存完成。

如果 Leaf 提示原文件找不到，或文件已被其他程序修改，请先保留当前编辑内容，按照提示重新定位文件或另存为。

**自动保存与草稿恢复是两件事。** 前者更新文档文件，后者保留可供意外中断后找回的编辑内容。重要文稿仍建议定期备份。

## 文档属性

文档属性用于记录正文之外的信息，例如作者、日期和标签。你可以在文稿顶部集中查看和编辑这些资料，无需把它们写进正文。

### 添加与编辑

在编辑视图中，将光标放在文档最开头的空白第一行，连续输入三个半角短横线 `---`，Leaf 会自动创建文档属性区域。你也可以在命令面板中搜索“文档属性”来添加。

点击“添加属性”，填写属性名和初始值，并选择适合的类型，例如文本、日期、数字或复选框。

已有属性可以直接修改名称和内容；点击属性类型图标，可以更改类型。需要删除某项属性时，将它的属性名和属性值都清空。

在编辑视图中，可以通过“显示 → 文档属性”展开或收起属性区域。收起只改变显示，不会删除属性。

### 保存与阅读

属性保存在 Markdown 文件开头的 YAML 区域，随文稿一起保存和移动，通常无需手写这些标记。源码视图会显示原始 YAML；结构较复杂、无法直接编辑的属性，请在源码视图中修改。

如果习惯直接输入，也可以切换到源码视图，在文档最开头用两行 `---` 包住属性，例如：

```yaml
---
日期: 2026-10-24
标签: [写作, 草稿]
---
```

**编辑视图中的正文全选不会选中文档属性。** 在正文中按 `⌘A`（Mac）或 `Ctrl+A`（Windows），只会选中正文，便于复制或替换文章内容时保留属性。如果需要连同属性一起复制或删除，请切换到源码视图，再全选。

属性不作为正文标题列入大纲。阅读视图会在文稿顶部呈现属性；导出 PDF 时，可以通过“文档属性”选项决定是否包含它们，默认不勾选。

## 编辑与阅读

### 选择适合当前工作的视图

| 视图 | 适合做什么 |
| --- | --- |
| 编辑 | 一边写作，一边看到标题、加粗、列表等格式的呈现效果。 |
| 源码 | 查看和修改原始 Markdown 标记，检查链接、空行或复杂格式。 |
| 阅读 | 通读排版后的文稿，减少编辑控件的干扰。 |

三种视图使用同一份文稿，无需在它们之间复制内容。需要修改正文、脚注或批注时，请切换到编辑或源码视图。

### 常用格式

可以直接输入 Markdown，也可以使用格式工具栏或快捷键，为文字添加加粗、斜体、高亮、删除线、链接，或插入标题、列表、引用、表格、代码块和提示块。

编辑表格时，可以直接修改单元格内容，并通过表格控件添加或删除行、列。需要检查原始写法时，切换到源码视图即可。

### 快捷键，随用随看

将鼠标悬停在相应控件上，即可查看快捷键提示。不必记住上百个快捷键，也能逐渐熟悉键盘操作，把注意力留给写作。

### 专注模式

需要更安静的写作界面时，可以开启“专注模式”。按 `Esc` 退出。

### 富文本复制、粘贴与拖放（1.0.4）

以下说明适用于准备中的 1.0.4；本页上方下载链接仍指向已发布的 1.0.3，待新版正式发布后更新。

使用“复制为富文本”（Mac `⌘⇧C`，Windows `Ctrl+Shift+C`）可以复制带格式的内容，同时提供可读纯文本回退；接收软件决定采用哪一种。普通复制与“复制为富文本”是不同入口。粘贴时，Leaf 将来源提供的 HTML 转换为 Markdown，而非保存原始网页排版；编辑和源码视图使用相同转换。若来源只提供标题纯文本，Leaf 无法还原其中未包含的链接目标。

外部富文本可拖到正文落点，整次插入可一次撤销；内部文字移动、图片导入和拖入 Markdown 文件打开文档保留原有行为。普通编辑预览会隐藏合法转义标记，光标进入相应字符时可编辑源码；源码视图中的 `\[` 是保留字面量方括号所需的 Markdown，不会从文件中删除。

Ripple 的有效 v2 来源链接会保留命名标签，包括正式版 `ripple-transcript` 和开发版 `ripple-segment-dev`。在编辑视图用 Mac `⌘`／Windows `Ctrl` 加单击打开链接，阅读视图可直接单击。保存、粘贴和拖放本身不会启动应用。需要安装并注册相应版本的 Ripple；其他软件是否保留或打开这些链接取决于该软件。普通网页、邮件、文档内锚点和相对文件链接仍沿用既有处理；不支持任意应用协议。

Mac 日用修复版已由用户验收；Windows 的构建、自动测试与用户安装验收分别记录，Windows 真实跨应用拖放和回跳尚待验收。

## 查看与审阅

### 大纲导航

大纲按照标题层级呈现文章结构。点击其中的标题，即可跳转到对应章节。如果某一节没有出现在大纲里，请确认它使用了标题格式。

### 脚注边栏

将光标放在需要插入注释的位置，使用“插入脚注”控件或快捷键，再填写脚注内容。正文以脚注标记指向脚注内容，边栏便于对照正文，总览注释并进行编辑。所有脚注亦可在文末看到。

在脚注边栏中，双击脚注内容或按 Enter 可以进入编辑；通过返回正文的控件，可以定位对应的引用标记。删除脚注时，会一并删除它在正文中的全部引用，操作可以撤销。

脚注采用 Markdown 脚注格式保存。若提示“缺少脚注定义”，可以切换到源码视图，检查引用标记是否有对应的定义。

### 文稿批注

在同一段落内选中文字，使用“添加批注”，即可记录修改意见；也可以把光标放在正文文字之间，为当前位置添加批注。

打开批注边栏，可以集中查看意见并定位正文。双击批注内容或按 Enter 可以编辑；删除批注会保留对应的正文文字。

Leaf 也支持 Obsidian 的隐藏式批注 `%%批注内容%%`：在编辑视图中保留原文，在阅读正文中隐藏，并在批注边栏列出。

脚注和批注共用右侧栏，通过对应标签切换查看。

## 显示与排版

### 主题、字体与阅读宽度

在“设置 → 外观与排版”中，可以选择浅色、深色或跟随系统主题，并调整正文字体、正文字号与正文最大宽度。

这些设置帮助你找到舒适的阅读与写作布局，不会将字体、字号或宽度写成 Markdown 正文。

### 显示行号

在格式工具栏的“显示”中开启“源码行号”，正文左侧会显示 Markdown 源文件的行号，方便定位和描述问题。

请注意，行号不是段落编号。一行文字因窗口变窄而自动折成多行时，仍属于同一源码行；编辑视图中的空白行可能不显示号码，因此号码不一定连续。

行号只是界面提示，不会加入或保存到文稿文字中。

### 标题分级序号

在“显示”中开启“标题多级编号”，Leaf 会按标题层级显示类似“1”“1.1”“1.2”的序号，帮助辨认文章结构。

**这些序号是虚拟的显示效果，不会添加到标题文字中，也不会写入 Markdown 文件。** 关闭后，标题恢复为不带这些序号的显示方式。

如果希望标题文字本身包含编号，请手动输入。这个功能也不同于正文中的有序列表。

### 段落空行整理

Markdown 中的空行用于分隔段落和不同内容块。“整理段落空行”可以补齐缺少的分隔、删除多余空行，并清理文档首尾空行。

在编辑或源码视图中，点击工具栏的“整理段落空行”；也可以在命令面板搜索这个名称。

**这项操作会修改整篇文稿的 Markdown 内容。** 需要还原时，一次撤销即可恢复整次整理。它与“显示”中的格式标记不同：格式标记只控制换行等标记是否可见，不会修改正文。

| 位置 | 整理结果 |
| --- | --- |
| 普通段落之间 | 保留一个空行；缺少时补充，多余时删除。 |
| 段落与标题、列表、表格等独立内容块之间 | 保留一个空行。 |
| 同一列表的相邻项目、父项与子列表之间 | 去除多余空行，保留层级和缩进。 |
| 列表项内部的多个段落 | 保留必要空行，避免结构改变。 |
| 文档开头和末尾 | 清理多余空白行。 |

例如，整理前：

```markdown
第一段
第二段


- 第一项

- 第二项
```

整理后：

```markdown
第一段

第二段

- 第一项
- 第二项
```

普通正文中，直接相接的两行文字会按两个段落整理，在中间补一个空行；列表项的续行不会这样拆开。如果你有意在同一段落内手动折行，请先确认是否需要整理。

文档属性、代码块、HTML 块、引用、提示块和脚注定义内部的空行会保留；跨行的行内格式也会受到保护。整理不会更改列表文字或缩进，但触及的有序列表会沿用自动编号规则，保持编号连续。

需要仔细核对整理结果时，可以切换到源码视图查看，再保存文稿。

## 图片与 PDF

### 图片管理

插入文档的图片会保存到文档旁的配套文件夹。例如：

```text
旅行笔记.md
旅行笔记.assets/
```

**移动、备份或发送文档时，请把 `.md` 文件和对应的 `.assets` 文件夹一起带上，保持相对位置不变。** 只发送 Markdown 文件，接收者可能无法看到其中的本地图片。

对于文稿中原本引用的其他本地图片，也需要保留它们对应的文件及相对路径。

### 导出 PDF

使用“导出 PDF”，先查看导出预览，再按界面提示保存。如果打开了系统打印窗口，请选择保存为 PDF。

预览用于查看文稿样式，不显示实际分页。导出后建议打开 PDF，检查标题、图片、表格和跨页位置。

脚注会作为文末注释呈现。**PDF 不包含文稿批注、隐藏式批注及批注标识。** 需要保留审阅意见时，请保留 Markdown 原稿。

## 草稿恢复与应用更新

### 找回未保存的修改

如果出现“有可恢复的内容”提示，可以点击查看；也可以进入“设置 → 保存与恢复”，选择“查看可恢复草稿”。

恢复内容会替换当前编辑内容，操作可以撤销。恢复后，请先检查文稿，再手动保存；恢复后自动保存会暂停，避免未经确认就覆盖文件。

“保存与恢复”中还可以设置恢复记录的保留时间，以及恢复最近一次保存前的版本。这些记录有保留期限，不替代长期备份。

### 检查更新

Leaf 1.0.3 可在应用内检查更新并查看发布说明，然后通过浏览器前往官方下载页面。请保存文稿并正常退出 Leaf，再手动安装新版：Mac 在“应用程序”原位置替换 Leaf，Windows 按安装器提示覆盖原安装。本版不会在应用内下载安装或自动退出重启。

在同一系统用户下，保留原安装位置、不卸载也不清空数据目录，正常覆盖安装会保留持久设置与应用数据。此说明不包含更换用户、迁移数据或移动隧道程序目录的情况。临时连接需要重新建立；外部 AI 软件（包括 ChatGPT）的 MCP 授权可能需要重新确认。

**Windows 更新提醒：** 如果安装过程中出现卸载步骤，请保持“删除应用程序数据”未勾选。在普通卸载中勾选此项会清除 Leaf 设置和 MCP 连接配置。正常替换旧程序文件是另一回事，可按提示继续。

使用 1.0.1 或 1.0.2 时，请先从发布页手动安装一次 1.0.3。

## AI 辅助编辑

Leaf 目前支持通过 MCP 连接 **ChatGPT、Claude（桌面版）和 WorkBuddy**，辅助编辑与审阅文稿。使用前需完成对应软件的 MCP 连接配置。

如需让 AI 读取和修改文稿，可在“设置 → AI 辅助编辑”中启用 MCP 连接。具体配置步骤见 [AI 辅助编辑与 MCP 连接](AI_CONNECTIONS.zh-CN.md)。

开启并连接后，AI 可以访问已打开的文稿，包括未保存的内容；相关文本会发送到你使用的 AI 服务。请按文稿内容与自己的需要决定是否启用。
